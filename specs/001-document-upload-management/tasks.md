# Implementation Tasks: Document Upload and Management

**Input artifacts:** [spec.md](./spec.md), [plan.md](./plan.md), [data-model.md](./data-model.md), [research.md](./research.md), [quickstart.md](./quickstart.md), [document-management.openapi.yaml](./contracts/document-management.openapi.yaml), and [constitution.md](../../.specify/memory/constitution.md).

## MVP First Strategy

The MVP is **User Story 1 only: upload and view strictly personal documents offline**. Implement and verify exactly these tasks before starting any later story:

**MVP task IDs:** `T001-T005`, `T005a`, `T006-T014`, `T015-T026`, `T045-T048`, `T050`.

MVP completion requires the existing application to keep working, an additive schema upgrade to preserve existing data, owner-only authorization, local storage outside `wwwroot`, atomic multi-file uploads with per-file metadata, cleanup after failures, authorized file serving, offline acceptance coverage, and the SC-003 usability measurement. `T027-T044` and deferred benchmark task `T049` are later/deferred tasks and must not be started as part of the MVP.

## Dependency and Security Rules

- Tasks are dependency-ordered; a task may start only after its listed dependencies pass.
- Every document read/write/download decision must be enforced in `DocumentService` or a lower business boundary, not only in Blazor UI.
- File content must remain outside `wwwroot`; never use an original filename or request path as a physical path.
- No Azure SDK, external scanner, internet dependency, password authentication, or destructive database recreation may be introduced.
- Real malware scanning is deferred for this offline training application. Size, extension/type, content-type, metadata, and authorization validation remain mandatory.
